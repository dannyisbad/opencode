Executes a command in a TTY-aware terminal session with full PTY support. Unlike the bash tool which spawns a new process for each call, this tool uses an interactive pseudo-terminal (PTY), giving commands access to a real TTY.

ONLY use this tool when the command genuinely needs a TTY or interactive stdin:
- Commands that require a TTY (sudo, ssh, vim, htop, top, gpg)
- Commands that need interactive input mid-run (passwords, passphrases, confirmations)
- Programs that check `isatty()` or require terminal features
- A persistent REPL you will feed input over multiple turns

For EVERYTHING else — including long-running non-interactive commands (builds, tests, dev servers, bots, watchers) — use the bash tool instead. Backgrounded bash (`background: true`, or automatic after the 30s foreground window) notifies you when the command exits; read incremental output with `bash_output` and stop it with `bash_kill`. Do NOT open a terminal session just to poll output you could get from bash — polling burns turns; bash notifies you for free.

Be aware: OS: ${os}, Shell: ${shell}

## Actions

This tool supports multiple actions via the `action` parameter:

### action="run" (default)
One-shot command execution. Creates a PTY, runs the command, waits for exit, then tears down the session.

A command still running after the foreground window (default 30s) is NOT killed — it is automatically moved to the background and you are handed a `sessionId`. You can also set `background: true` to background it immediately. PREFER `background: true` for commands that block, run indefinitely, or wait for interactive input — dev servers, file watchers, `npm run dev`, `tail -f`, REPLs, build/test watch loops, long `ssh` sessions. When a command is backgrounded you are notified when it exits; meanwhile use `action="read"` with the returned `sessionId` to read output incrementally, `action="send"` to provide input, and `action="close"` to stop it.

- `command` (required): The command to execute
- `background` (optional): Run in the background and return immediately with a sessionId. Default false (foreground, auto-backgrounds after the timeout window).
- `timeout` (optional): Foreground window in milliseconds before auto-backgrounding (default: 30000ms). The command is NOT killed at the timeout — it keeps running in the background.
- `workdir` (optional): Working directory (defaults to current directory)
- `description` (required): Brief description of what the command does

Example (background a dev server):
```json
{ "command": "npm run dev", "description": "Start dev server", "background": true }
```

### action="create"
Create a persistent interactive PTY session. The session stays alive between tool calls, allowing you to send input and read output incrementally.

- `workdir` (optional): Working directory for the session
- `description` (optional): Description for the session

Returns a `sessionId` that you use with `send`, `read`, and `close`.

Example:
```json
{ "action": "create", "description": "Interactive Python REPL" }
```

### action="send"
Send input to an existing session. Input is appended with a newline automatically for commands. For control sequences, use escape codes:

- `sessionId` (required): The session ID from `create`
- `input` (required): Text to send. Use `\x03` for Ctrl+C, `\x04` for Ctrl+D, `\x1a` for Ctrl+Z
- `description` (required): Brief description of what this input does

Example (run a command):
```json
{ "action": "send", "sessionId": "pty01ABC", "input": "ls -la", "description": "List files" }
```

Example (send Ctrl+C):
```json
{ "action": "send", "sessionId": "pty01ABC", "input": "\x03", "description": "Interrupt running process" }
```

### action="read"
Read new output from a session since the last read. Output is cursor-based — each read returns only what was produced since the previous read.

- `sessionId` (required): The session ID from `create`
- `description` (required): Brief description of what you are reading

Returns the new output and the session's exit code if the process has exited.

Example:
```json
{ "action": "read", "sessionId": "pty01ABC", "description": "Check output" }
```

### action="close"
Terminate a persistent session and clean up resources.

- `sessionId` (required): The session ID to close

Example:
```json
{ "action": "close", "sessionId": "pty01ABC" }
```

## Session Lifecycle

1. `create` → get a `sessionId`
2. `send` → send commands or input
3. `read` → check output (repeat as needed)
4. `close` → terminate when done

Maximum concurrent sessions: 20. Oldest sessions are evicted automatically.

## Usage Notes

- All commands run in the current working directory by default. Use the `workdir` parameter if you need to run a command in a different directory. AVOID using `cd <directory> && <command>` patterns - use `workdir` instead.
- IMPORTANT: This tool is for commands that REQUIRE a TTY. For simple non-interactive commands (git, ls, npm, docker), prefer the `bash` tool instead — it is faster and more efficient for non-interactive operations.
- The command argument is required for `action="run"`.
- `timeout` is the foreground window (default 30000ms) — a command still running at the timeout is auto-backgrounded, NOT killed. Set `background: true` to background immediately.
- It is very helpful if you write a clear, concise description of what this command does in 5-10 words.
- If the output exceeds ${maxLines} lines or ${maxBytes} bytes, it will be truncated and the full output will be written to a file.
- The PTY echoes input, so you may see the command repeated in the output. This is normal and is automatically filtered.
- stdout and stderr are combined in PTY output (no separate streams). This is inherent to the PTY model.
- For interactive programs that wait for user input (like `sudo`), the command stays in the foreground until it exits or the timeout window elapses (then it auto-backgrounds). To interact with it, either pass `background: true` (or let it auto-background) and use `action="send"`/`action="read"` on the returned sessionId, or use `action="create"` up front for a dedicated interactive session.

## Exit Code Detection

On Windows PowerShell, the exit code is detected using `$LASTEXITCODE`. On Unix shells (bash, zsh, sh), `$?` is used.

## Examples of when to use terminal vs bash:
  - `ssh user@host` → Use **terminal** (requires TTY)
  - `sudo apt update` → Use **terminal** (requires TTY for password)
  - `gpg --gen-key` → Use **terminal** (requires TTY)
  - `htop` → Use **terminal** (requires TTY)
  - `git status` → Use **bash** (no TTY needed, faster)
  - `npm install` → Use **bash** (no TTY needed, faster)
  - `ls -la` → Use **bash** (no TTY needed, faster)
